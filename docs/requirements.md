# System requirements specification

**Status:** Initial requirements and architecture direction approved by the stakeholder on 2026-11-09; implementation of the first slice is authorized. Unresolved operational parameters remain open.
**Baseline:** [User stories v0.3](user-stories.md). IDs below are reserved and must not be reused. Requirements are V1 targets unless explicitly marked Future or pending a decision; all are subject to vertical-slice and sizing review. Each acceptance criterion is a proposed verification oracle, not evidence of a completed test.

The target operating environment is POSIX systems, with the supported platform matrix to be defined. The system is a standalone Rust product, independent of model and orchestration framework. Messaging and durable state serve agents independently of the human attention interface. “Accepted” means the system has positively acknowledged a submission after its durability boundary; the precise storage failure model remains open. In V1 a participant is an agent or operator in one trusted local user context; participant labels are not authenticated identities; an activity is a supplied correlation reference, not a managed project. “Pending communications” in SYS-033 means messages accepted by the system for that agent and not yet retrieved under the eventual delivery policy.

## Scope and unresolved interpretation

The selected initial architecture uses a central service. The requirements do not prescribe a transport, storage engine, agent hierarchy, project-management features, or orchestration. V1 is single-user, binds to localhost by default, and may explicitly bind a selected network interface on a trusted local cluster. It has no application authentication or authorization. Channel addressing is routing, not a security boundary against processes able to reach the service. Multi-user isolation and network authentication are Future. SYS-033 covers communications accepted while the recipient is disconnected; it does not require an unreachable service to accept a submission or guarantee delivery under indefinite outage. V1 supports a targeted agent-to-agent request and one correlated response using the shared channel communication model. Richer autonomous coordination remains subject to the V2 and Future stories; no agent orchestrator is implied.

The operator ultimately controls importance; an agent may suggest or infer a default. Agent suggestions and operator overrides suffice for V1; configurable rules are not required. The initial implementation uses explicit sender-selected operation types for attention classification; classification quality and timing thresholds remain to be validated. The corresponding tests verify ordering or eventual visibility under controlled conditions, not an invented production service level. Requirements with these unresolved parameters cannot be considered fully baselined until reviewed. Suggested-answer count has no arbitrary product limit specified; practical resource limits remain to be decided and disclosed. A default selection is not a submission: an explicit confirmation is required. For SYS-045, group addressing reaches all `all` members except the operator; a First Mate is optional and its inbox monitoring is external to Aviary. Provisioning `all` and its members remains an open implementation decision.
